# Art Provenance

> Which drawings are from datasheet package outlines, which are stylised,
> and confirmation that nothing is traced from a third-party asset.

## Drawing methodology

Every SVG in `parts/` was created in one of two ways:

### 1. DIP-generated (27 chips)

Generated by `generate-dip.js` from a parametric template. The template
produces a generic DIP package body (black rectangle, notch, pin-1 dot,
pin labels) — the visual is **stylised**, not traced from any specific
manufacturer's package drawing. The pin labels and pin-to-position
mapping come from manufacturer datasheets:

| Chip | Datasheet source |
|---|---|
| 74HC00/02/04/08/10/11/14/20/21/27/32/73/74/86/93/95/132 | TI 74HC-family datasheets (SCLS series) |
| 74HC75 | TI SN74HC75 (SCLS154) |
| 74HC283 | TI SN74HC283 (SCLS108) |
| 74HC595 | TI SN74HC595 (SCLS146) |
| CD4017 | TI CD4017B (SCHS027) |
| CD4511 | TI CD4511B (SCHS052) |
| PCF8574 | NXP PCF8574 Rev 5 |
| NE556 | TI NE556 (SLFS023) |
| LM393 | TI LM393 (SLCS007) |
| LM339 | TI LM339 (SLCS006) |
| ATtiny85 | Microchip ATtiny85 datasheet |
| STC12C5A60S2 | STC Micro STC12C5A60S2 datasheet |

The DIP body shape is generic (all 14/16/40-pin DIPs look the same);
the pin names are factual data from the datasheets. No package outline
drawings were traced.

### 2. Hand-drawn (88 parts)

All hand-drawn SVGs are **stylised bench-style representations** created
from scratch by the agent. They depict the general appearance of each
component type (a resistor has colour bands, an LED has a dome, a servo
is blue with a horn) but are not traced from any specific manufacturer's
photograph, technical drawing, or third-party SVG.

The visual register is "photoreal-ish front view" inspired by the
wokwi-elements library (MIT, https://github.com/wokwi/wokwi-elements;
documented in THIRD-PARTY.md), but no SVG paths, coordinates, or code
were copied from wokwi-elements or any other source.

### Terminal positions

Terminal coordinates in JSON sidecars are placed at physically plausible
positions on the drawing (where the legs would be on a real component).
For parts where bw-circuit-ui already defined terminal offsets in
`BoardCanvas.jsx:terminalOffsetsForPart()`, positions were computed to
match the UI's existing offset convention. This mapping is documented
in `spec-updates/001-terminal-position-alignment.md`.

For DIP-generated chips, terminal positions are mechanically determined
by the pin count and spacing — they are not hand-placed.

## Confirmation

**No SVG in this repository is traced from, derived from, or contains
paths copied from any third-party asset.** All drawings are original
work. The only external inputs are:

1. Manufacturer datasheet pin assignments (factual data, not
   copyrightable)
2. The wokwi-elements visual style as a reference for the rendering
   register (no code or paths copied)
3. Standard component appearances (what a resistor, capacitor, or
   DIP package looks like) which are generic physical descriptions

## Four unverified identifications

These parts are drawn in a generic form because the specific variant
is uncertain. The uncertainty is documented in the JSON sidecar `_note`
field and in `PARTS-CATALOG.md`:

| Kind | What is generic | Why |
|---|---|---|
| `clock_display` | Terminal names use clk/dio (could be scl/sda) | HT16K33 vs TM1637 unresolved |
| `attiny85` | Pin map assumes ATtiny85 | Could be ATtiny45/25 |
| `microbit` | Board shape is generic | v1 (nRF51822) vs v2 (nRF52833) unresolved |
| `gas_sensor` | Generic MQ-style can | MQ-2/3/4 span different gases |
